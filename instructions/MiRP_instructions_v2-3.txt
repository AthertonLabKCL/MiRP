--------------------------------------------------------------------------------------------------------------------

PREPROCESSING

--------------------------------------------------------------------------------------------------------------------

1. Import micrographs (FULL DOSE)

2. Run CTFFIND4 or gCTF using GPU on FULL DOSE micrographs. Adjust parameters according to your dataset. After this point make sure you are using dose-weighted micrographs for all
subsequent steps.

3. Select best micrographs; remove those with poor power spectra (indicating perhaps poor motion correction) or ice contamination.

4. Use relion's manual picker (picking with start-end coordinates for helicies) to pick straight and undamaged regions of MTs.
		
5. Extract 4x binned particles from these coordinates in helical mode;
		Input Coordinates: *coords_suffix_manualpick.star file in manual pick job*
		OR re-extract refined particles? No
		Refined particles star file: N/A
		Re-center refined coordinates: No
		Particle box size (pix) = ~600A (432 pixels if 1.39A/pixel).
		Rescale particles? Yes
		Re-scaled size (pixels): *Original particle box size/4*
		
		Extract helical segments = yes
		Tube Diameter (A) = 400
		Use bimodal angular priors? yes
		Coordinates are start end only? yes
		Cut helical tubes into segments? Yes
		Number of asymmetrical units: 1
		Helical rise (A): 82
		
N.B Try using multiple MPI without GPU- e.g 24 MPI 1 Thread.
		
6. Scale helical track length; some RELION v3.0 versions do not scale helical track length column properly when changing particle binning. Therefore you need to run the script scale_helical_track_length.csh on the binnedx4 extracted particles.star file to scale the track length (source scale_helical_track_length.csh particles.star 0.25). CHECK IN STAR FILE TO SEE THAT TRACK LENGTH CHANGE BETWEEN BOXES IS CORRECT (~82A)

DATA OPTIMISATION FOR MiRP - WORKING ON WHOLE MT SEGMENTS

------------------------------------------------------------------------------------------------------------------------

The following can be used to try and improve your data once you have your rough alignment parameters and you have moved to 1xbinned data, either before or between iterations of the high-resolution refinement step.
The use of these steps depends hugely on your sample/data.

1. You can try running an additional supervised 3D classification of 2 references: one with decorating protein and one without (just tubulin). 
In my hands this gives you a class with good decoration and one with poor decoration. Do a further refinement on the class with good decoration. This will probably give you a better decorated map and perhaps a better seam but perhaps at the cost of resolution if you don't have many particles. N.B THIS IS ESSENTIALLY REDUNDANT IF YOU ARE GOING ON TO DO FOCUSSED EXTRACTION THEN CLASSIFICATION, WHICH CLASSIFIES DECORATION AT THE ASYMMETRIC UNIT LEVEL. 

2. Try iterative rounds of Bayesian Polishing,CTF Refinement and local refinement- can improve reconstruction resolution. N.B THESE ARE BEST DONE ON WHOLE MICROTUBULE SEGMENTS BEFORE FOCUSSED EXTRACTION AS YOU GET BETTER SIGNAL FROM WHOLE MICROTUBULES AND THE REFERENCES AFTER FOCUSSED EXTRACTION (A 3D ASYMMETRIC UNIT) DO NOT MATCH WELL WITH THE RAW EXTRACTED IMAGES (THAT MAY INCLUDE MANY OVERLAPPING AUs FROM ALL WALLS OF THE MICROTUBULE).

3. Try running a 3D classification with no alignment with 2 classes with your output reconstruction as a reference you will get poorly aligned particles coming out in one of the 2 classes (class will look poor)- then you can keep the good particles. N.B IF YOU ARE GOING ON TO DO FOCUSSED CLASSIFICATION, WHICH CLASSIFIES QUALITY AT THE ASYMMETRIC UNIT LEVEL, THIS MAY BE LESS USEFUL BUT IS STILL WORTH TRYING (MAY CLASSIFY OUT COMPLETELY MISALIGNED MT SEGMENTS).

4. You can manually check particles by plotting ROT angles against particle numbers and checking you have straight lines within particle from each microtubule. This is a good way to check the protocol has worked well for your dataset. To make the plots, you could either use a standard data analysis program like Excel or Prism, or use the mirpy.py script (python mirpy.py -p *_data.star). N.B PROB WORTH DOING THIS FOR SOME SMALL PORTION OF YOUR DATA AT LEAST, JUST TO CHECK MiRP HAS ACTUALLY WORKED OK!

The following should be used at earlier stages of the process;

5. You may want to remove short microtubules from your dataset if you are unconvinced by the angular and translational assignments, as a) shorter microtubules give less statistical certainty for pf number/seam allocations and b) particles towards the ends of MTs include less averaged particles in their segment averages and thus have lower signal to noise. The mirpy.py script can be used for this (e.g for minimum length 10 particles; python mirpy.py -s *_data.star -lw 10). N.B AGAIN, MAYBE LESS IMPORTANT IF GOING ON TO FOCUSSED CLASSIFICATION/REFINEMENT?

6. You can pick individual MTs based on how internally consistent (particles within a single MT) their protofilament number sorting or seam check class allocations were. This will probably give you a better seam but sometimes at the cost of resolution if you are low on particles. You can use the mirpy.py script can be used for this, to show confidence plots and/or provide a cutoff (e.g to make a confidence plot; python mirpy.py -c run_it001_data.star, to cutoff MTs below 50% confidence of a class assignment; python mirpy.py -c run_it001_data.star -lw 50). N.B AGAIN, MAYBE LESS IMPORTANT IF GOING ON TO FOCUSSED CLASSIFICATION/REFINEMENT?

SYMMETRY EXPANSION

------------------------------------------------------------------------------------------------------------------------

Symmetry expansion is quite a simple process- you basically take your final .star file from working on microtubule segments and perform a relion operation that creates a new .star file that includes copies of each line representing each particle, that are transformed based on the symmetry of your microtubule. No new MT segment particle images are generated however. Therefore, for example, with a 13pf, the new star file will contain 13 fold more particles, 13 for each original segment (13 linked to each original segment image). This allows you to place a mask or extract on a particular asymmetric unit in each segment.

1. Go to the directory containing you final binx1 .star file (c1 high-resolution refined, after classification for segment quality, polishing and CTF refinement if these are performed). 

2. Use the relion_particle_symmetry_expand command from the Relion home directory specifying helical parameters for your microtubule. I feel the best option is to run a symmetrised high-resolution refinement run (see above), which allows relion to refine your helical parameters, and use these refined helical parameters as input. Alternatively, one can use the 'expected' parameters for a MT of that pf number/start number. Or you can run the command on an output reconstruction to get helical parameters, e.g;
relion_helix_toolbox --search --i ./PostProcess/job025/postprocess.mrc --cyl_outer_diameter 400 --cyl_inner_diameter 120 --twist_min -27 --twist_max -28 --twist_inistep 0.1 --rise_inistep 0.1 --rise_min 9.4 --rise_max 9.7 --z_percentage 0.3

Example symmetry expansion command for a 13pf below (I don't fiddle with the other parameters);

relion_particle_symmetry_expand –-i Refine3D/job123/run_data.star –-o Refine3D/job123/run_data_sym_expand_rise_9-6_twist-27-68.star –-helix –-twist -27.6786 –-rise 9.60866 –-asu 13

FOCUSSED EXTRACTION

------------------------------------------------------------------------------------------------------------------------

Now extract new smaller particles centred on the asymmetric unit, for each asymmetric unit, for further focussed classification and/or refinement:

1. Open Chimera X and your map.

2. Open the volume eraser GUI and make it a small sphere, then move it to the point of your map where the new centre should be. Now click on 'Erase outside sphere', to leave a ball of density centred on your planned centre of extraction.

3. Now run the following command to identify the density center of your map; measure center #<your-erased-map-model-number> level contour-level 0.01 mark true radius 5 color red
In the log window, a 'Center of mass grid index' in pixels will be reported, i.e 303.28, 151.44, 278.88, and a marker will be placed at that point.

4. You then need to subtract the centre of the box coordinates in pixels from your new coordinates in pixels. The centre of the box in pixels will always be your box size/2 so for a box size of 560, the centre in x,y,z will be 280,280,280. For this example, your final coordinates for input into relion are 23.28,-128.56,-1.12.

5. Enter this into 'recenter on - X, Y, Z (pix)' line in the RELION extraction job (recenter on refined coordinates) and rextract using a box size 1.5-2x the size of the asymmetric unit. You should probably do a binned x2 extraction (using Re-scaled size in pixels as before) if you plan to do multiple focussed classification or refinement steps/test classifications, then rextract binx1 particles to do a final refinement/reconstruction. 

6. Do a reconstruction only from the new extraction star file (or even a sub-subset of it) to check a centred asymmetric unit is generated. 

Now we can refine the asymmetric unit and classify for MAP occupancy for example- see example next steps;
